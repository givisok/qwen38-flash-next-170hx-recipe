# Tuning 2026-10-27 — prefix-cache knobs from the g4bwy recipe

Source: github.com/g4bwy/qwen3.8-flash-next-cmp-170hx (same Qwen4Exp/170HX
ecosystem, 4-card FP8 lane). Applicable parts ported config-only; measured here.

## Changed

1. `configs/awq-1m-fp8-ssmbf16.yml` (backup: `.bak-pre-g4bwy`):
   - `prefix-cache-retention-interval: 17280` (was default 0; 17280 = 10× block 1728)
   - `prefix-match-unit: 16` (was default = block 1728)
2. `run-qwen38fn.sh` (backup: `.bak-pre-g4bwy`):
   - `-e NCCL_IB_DISABLE=1`
   - `-e PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`
   - default `IMAGE` → `vllm-sm80:q38fn` (nightly tag absent from this docker;
     plain `./run-qwen38fn.sh` failed with "No such image" after rm -f)
3. `max-num-batched-tokens` 10368 (=6×1728, aligned) was A/B-tested and REVERTED
   to 8192: prefill +2% (noise), KV pool −2.6% (4.33x → 4.22x).

## Measured (32k-token prompts, fp8 KV, pool 4.33x)

| cell | before | after |
|---|---|---|
| repeat 32k, % cached | 91.8% (recompute 2636) | 99.9% (recompute 28) |
| grown +200 words | 91.2% (recompute 2836) | 99.3% (recompute 228) |
| short 512-token repeat | 0% (under 1728 floor) | 96.9% |
| decode, cache-hot | 146–163 tok/s | 177–181 tok/s |
| cold prefill | 3.2–3.5k tok/s | unchanged (NVMe PLE staging bound) |

Decode degrades toward ~60 tok/s when the 51 GiB PLE n-gram table's hot pages
get evicted from page cache (host has 31 GiB RAM total — pinning like g4bwy
does is impossible here). Synthetic junk-prefill benches evict it; real agent
traffic has a compact hot set. After-boot decode = the ceiling.
