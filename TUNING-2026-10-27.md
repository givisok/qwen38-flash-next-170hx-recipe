## 2026-10-28: long-prefill-token-threshold 2048 (multi-user decode protection)

`long-prefill-token-threshold: 2048` added to the config. Measured with a
contention probe (decode stream A + 120k-token prefill B arriving at t+2s):

| | A events during B (31-32s) | A stalls >1s | B TTFT |
|---|---|---|---|
| no LPT | 8 (stream frozen) | — | 32.4 s |
| LPT 2048 | 74 (bursty but alive) | 22, max 1.56 s | 31.0 s |

Solo long prefill is untouched by design (threshold only applies when other
requests exist): 60k solo = 14.0 s / 4.3k tok/s. KV pool unchanged (4.33x).

Why bursts remain: under fp8 KV the attention-group block is 2x1728=3456
tokens, so prefill chunks cannot be smaller; one chunk's PP=3 pipeline
traversal ~=1.5 s and decode squeezes between chunks. Caps <=3456 all behave
the same. Fully smooth interleaving needs the AlexBrandes scheduler commit
("[v1][Scheduler] Bounded prefill budget beside running decodes (hybrid
Mamba)") ported onto the fork.

## 2026-10-28: autostart after host reboot (root cause + fix) + RAM upgrade

Symptom: after a host reboot the model did not come back. Root cause: the
original container (2026-10-22) had been created with `--restart
unless-stopped` by hand, but `run-qwen38fn.sh` never passed `--restart` —
every container recreated by the launcher silently had `policy=no`, so after
the host reboot docker left it `Exited (0)`. Fix: `--restart unless-stopped`
added to the launcher's docker run; live container updated via
`docker update --restart unless-stopped qwen-intel`. After a real reboot
/dev/shm is a fresh tmpfs, so the launcher's stale-shm cleanup concern does
not apply to policy restarts; boot to ready ~4.5 min.

Host RAM upgraded 31 -> 46 GB (user, 2026-10-28). CT 101 memory raised
26 -> 36 GB (hot, pct set): the 51 GiB fp8 PLE table's page cache was capped
at the old CT limit (~25 GB effective) — now ~70% coverage.

Traps: `docker start` on an old container shows the container's full log
history — poll with `docker logs --since`, not `grep -c startup complete`.

kv_holding_waiting instead of skipped_waiting — see patches/fn12-bounded-prefill.diff).

(default 864; 0 = off, flag-off is byte-identical). scheduler.py added to the

tokens.

## 2026-11-04 (afternoon): second crash — hash promotion; aligned publications are not partial

14:58 UTC, ~20 h after the CoW fix (which never fired — zero [partial-cow]):
`cache_full_blocks` died on the promotion assert — a "new full block" carried
a hash whose token count was not strictly below the full hash's. Cause: an

the chain hash AT the full token count; `cache_partial_block` does not guard

killed the engine.

diff: patches/hash-promote-fix.diff.

partial-hash machinery — it degrades (one entry retracted, one landing
shallower, one offer skipped) and logs, never dies. Family audited; remaining
asserts are structural.
