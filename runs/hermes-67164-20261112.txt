## The port (upstream #67164 semantics in OUR engine's idiom; their diff
targets a newer refactored qwen3.py — does not apply to us)
1. content_events gains TOOL_PREAMBLE -> ARG_VALUE_CHUNK: the JSON body
   text now reaches the call's args (default dict had no entry -> text
   dropped in _emit_for_state). Whitespace before the trained <function=
   is invisible to the XML converter -> trained path unchanged.
2. _qwen3_arg_converter: JSON branch first (_qwen3_json_body_args): body
   starts with '{' -> complete body returns the arguments JSON
   (arguments/parameters key, str-args passthrough, name stripped);
   incomplete during streaming returns "" (defer to close — no partial
   garbage deltas, matches _compute_arg_delta's `if not current_json`);
   not JSON -> None -> XML fallback untouched.
3. Qwen3Parser._try_extract_name override: args starting '{' parse
   exactly when complete (top-level name); partial streaming falls back
   to the base regex ONLY ahead of "arguments"/"parameters" keys — a
   literal "name" argument nested inside arguments cannot steal the call
   name (upstream's guard; tools with a name= arg are common).

Recovery machinery already in our base (upstream had to add it):
_try_extract_name hook points, _extract_name_and_args split,
_accept_tool_name gating (validate_tool_names covers the new path).
