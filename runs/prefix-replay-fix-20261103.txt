# Prefix-cache replay DEPTH fix — 2026-11-03 (prod MTP-4, hybrid GDN)
# Patch: patches/prefix-replay-depth.diff (fork commits 8a63b11..HEAD)
# Probes: scripts/prefix_probe.py, scripts/depth_diag_probe.py,
#         scripts/greedy_gate3.py. Upstream class: vllm-project/vllm#52244.

## Symptom (before)
Identical resend of a just-prefilled prompt hit the cache far below its depth:
  depth_diag (8231-token body, 3 sends): 0 -> 5184 -> 8208 tok
  prefix_probe (4 unique bodies):
    A  4773 tok -> 2368 (50%)   B  5152 -> 4752 (92%)
    C  7115 tok -> 5184 (73%)   D  8230 -> 5184 (63%)   <- hard ceiling 3x1728
Every same-context agent turn re-prefilled 8-50% of an already-cached prompt;
on a 25k neighbor that is 2-12k avoidable prefill tokens = storm fuel.

## Root cause (unit mismatch across the publish/lookup chain)
Runtime: block 1728, prefix_match_unit 16 (fine-grained lookups), MTP-4
(drop_eagle=True), mamba align mode, retention interval 17280.
1. The LOOKUP lands at the hash unit: cap (prompt_len-1), then one hash unit
   of eagle rewind -> 8208 on an 8231 prompt. The attention group already
   registered and hit at that depth.
2. The mamba PUBLISHER never keyed the landing on the first pass:
   - allocate_slots records transient checkpoints at (chunk_end+lookahead
     floored) - 16 -> 8192 for the 8208-chunk: never equal to the prompt
     boundary (8208), so the transient branch evicted the block instead of
     keeping it (and took the 6912 full-block hash with it);
   - the FALLBACK re-key path (which does key the landing, blocks[
     cdiv(8208,1728)-1]) only accepted num_tokens == boundary exactly, but
     the final caching pass arrives at boundary+3 (the re-prefillable spec
     tail is excluded from cacheable tokens) -> rejected every time.
   Net surviving entry after a cold prefill: the coarse retained state at
   5184 (get_replay_boundaries' resend - block). The second replay's own
   pass happened to key the landing (its chunks start from the hit), which
   is why the third send hit 8208 — the system self-healed one send late.
3. get_replay_boundaries retained only coarse (resend - 1728) states.

## Fix (3 pieces, mirrors upstream #52244 mechanics)
- MambaManager._cache_partial_tail_block: accept the COMPLETION caching pass
  (boundary < num_tokens <= prompt_len) and key AT the landing boundary on
  blocks[cdiv(boundary, block)-1]; decode passes stay excluded.
- FullAttentionManager._cache_partial_tail_block: also register the
  (prompt_len-1) hash-boundary landing (deepest first) so prompts ending on
  a block boundary keep a reachable tail entry.
- KVCacheCoordinator.get_replay_boundaries: also emit fine-grained landings
  at min(hash_block_size, scheduler_block_size).
Plus an env-gated [rekey-diag] log (VLLM_CACHE_DIAG=1).
