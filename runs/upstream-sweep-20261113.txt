## The find: vllm#67427 (opened 11-13, fixes #67425) — no-tools content loss
Chain (their writeup, matches our base): a request WITHOUT tools still has
tool_choice default "none" -> DelegatingParser._extract_tool_calls takes the
"none" branch but STILL runs the engine parser -> markup consumed into
tool_calls, content becomes None -> response builder drops the calls
(request declared no tools) -> client gets content=null, finish=stop,
tokens burned, NOTHING logged. Same silent-loss class as the hermes bug;
plausibly the other half of the historical "pi just stops" sessions
(analysis turns without tools).

PROVEN on our stack (CT /root/qwen38fn/tools/notools_probe.py, CPU stand,
prod parser binds, engine parser driven directly, request tools=None):
  case             parser result                     client-visible
  real-xml call    content=None, call 'calc'          TOTAL LOSS (call dropped)
  hermes call      content=None, call 'calc'          TOTAL LOSS
  markup-in-text   surrounding text kept, markup torn PARTIAL LOSS (example
                   out + call dropped                 silently deleted)
With no tools offered our name gate accepts ANY name (by design
_is_valid_tool_name: no tools -> True) — the swallow is unconditional.

Their fix (vllm/parser/abstract_parser.py, 2 x ~6-line hunks):
non-stream `if not request.tools: return [], content` before the
tool_choice=="none" branch; streaming same shape (return the raw delta as
content). Reasoning extraction is NOT affected (content arrives
reasoning-stripped). Narrow scope: does not touch tool_choice="none" WITH
tools declared (separate semantics question #55080/#55089).
Our anchors verified: _extract_tool_calls @382-393,
_extract_tool_calls_streaming @684-703 — same shape as upstream pre-fix.
Port = 2 hunks + 1 NEW launcher bind (abstract_parser.py not bound yet)
+ battery extension. Revert = remove the bind.
