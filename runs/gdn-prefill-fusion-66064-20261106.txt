## Part 2: [partial-cow] vacated-slot upgrade (fork 9794d18ed6 + 6646825df6)
The 40 prod degradations of 11-05 were ALL this shape: slot = _null_block
(block_id 0), marker intact — the signature of _relocate_speculative_block
(exactly 4/request = MTP-4 spec slots), which APPENDS the block to the
table tail and nulls the old slot. The publication still describes the
request's true history (cached blocks are immutable while hashed), so the
old behavior (evict the hash) threw away a valid landing state 40x/day.

New consume logic (patches/partial-cow-vacated-slot.diff):
- slot is source_block + marker ok -> happy CoW (unchanged)
- NEW: slot is _null_block + marker ok -> KEEP the publication, INFO log
  "publication kept"; only the directed CoW shortcut is lost; the generic
  hit/CoW path re-attaches the prefix on the next lookup
- anything else (real rewrite / marker mismatch / past-end) -> unchanged
  warn + evict (the [partial-cow] WARNING is again a true anomaly signal)

Tests (tests/test_cow_promotion_guards.py, fork copy updated): 5/5 green on
the unit stand — the old stale test was retargeted to a REAL rewrite (it
used to simulate the null-slot case, which is now the benign branch; it
also exposed that a NEW landing record on the rewrite block is legitimate
tail bookkeeping, assertion fixed), plus the new
test_producer_slot_vacated_by_relocation_keeps_publication.
